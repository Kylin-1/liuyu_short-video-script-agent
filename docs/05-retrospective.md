# 项目复盘

## 问题一：将业务目标落实为创作任务

早期脚本偏向展示商品细节，带货目标与剧情形式没有充分分开。迭代后，Brief 分别记录商业目标、内容形式、风格、转化动作和入口。编剧围绕人物目标与阻碍组织情节，导演保留操作和结果的连续性，结尾承接指定行动。

这次调整说明，结构化需求需要描述下游如何做决策。单独记录“带货”或“生活化”等标签，还需要配合目标、素材及转化要求。

## 问题二：给创作留空间，同时约束产品主张

事实检查曾采用严格的原文与模板匹配，测试中出现合法对白被转入复核的情况。模型模式随后增加独立语义审核，将人物情境与产品主张分类处理，代码检查字段覆盖和引用原文。

形成的设计原则是：素材支持产品主张，创作角色组织人物与情节，审核角色检查两者的关系。效果评估同时关注无依据主张和合法表达的处理情况。

## 问题三：让返修结果重新接受检查

返修会改变时长和审核对象。当前实现将检查报告与稿件版本绑定，改稿后使旧报告失效，再执行分镜、工具检查和审核。定向修改同时保护事实镜头、锁定创意和转化入口。

时长处理采用超标触发策略。导演调整停留时间时保留动作下限；创作评审继续检查因果和节奏。数值约束与内容质量分别有对应的检查步骤。

## 验证方法

离线用例用于复现边界与失败分支；HTTP协议测试用于检查角色接线和数据契约；外部模型运行与人工内容评价用于检验实际创作。验证结果按层记录，便于定位问题来源。

## 后续计划

1. 完成外部模型的正常、超时、空素材和工具故障路径，分析实际失败原因。
2. 建立带人工标注的主张、引文及创作评价样本。
3. 使用试读或TTS音频校准估时误差。
4. 依据实测结果调整提示、契约及返修策略，进行同输入对照。
