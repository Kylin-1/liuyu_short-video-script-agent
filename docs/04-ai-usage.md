# AI 使用与个人贡献

## AI 辅助范围

本项目使用 AI 辅助完成方案讨论、代码草稿、合成测试数据、测试用例和文档整理。主要使用场景包括：

- 参考 AutoGen 的多 Agent 角色分工与反馈协作思路，梳理制片人、编剧、导演和审核角色的初始职责。
- 辅助编写状态机、角色适配器、业务工具、模型接口和数据契约。
- 生成合成素材、边界用例及部分自动测试草稿。
- 根据测试结果和人工检查意见定位问题、修改实现并整理运行记录。

所有进入仓库的代码、测试材料和说明均围绕本项目的数据契约与验收要求进行调整，并通过仓库内的可执行测试和示例结果验证。

## 个人贡献

我负责确定项目目标、架构取舍、业务数据契约和验收标准，并对生成结果进行迭代审查。主要工作包括：

- 选择短视频脚本方向，确定中文输出以及商品带货、到店引流和活动推广等核心场景。
- 将自然语言制作需求整理为结构化 Brief，区分商业目标、内容形式、风格、转化动作、硬约束和创意偏好。
- 设计制片人统一决策、编剧与导演分工、工具反馈和质量评审闭环；结合项目范围，使用原生状态机实现 AutoGen 式角色协作，并明确模型与确定性代码的职责。
- 发现“带货”被简化为商品展示的问题，补充人物动机、剧情转折、商品作用和结尾兑现等创作要求。
- 设计事实字段、画面字段、操作字段和素材 ID 的关联方式，限制无依据产品主张。
- 推动编剧、导演、事实审核、制作审核和创作评审接入模型接口，并保留离线 Mock 入口。
- 明确目标时长是上限，只在实际超标时触发文案压缩或镜头调整。
- 使用正常、缺信息、无素材、工具失败、时长修订和无法满足等场景反复检查输出与决策路径。

## 人工修改与验证

AI 生成的初始内容经过了以下人工判断和定向修改：

- 将固定商品展示模板调整为由商业目标和内容形式共同驱动的脚本生成。
- 将自由文本输入升级为带字段来源、缺失项和冲突信息的结构化 Brief。
- 将单一制片人模型调用扩展为多个专业角色的独立模型任务。
- 将时长检查、品牌规则、事实依据、制作质量和创作质量拆分为可分别定位问题的检查环节。
- 增加稿件版本失效机制，确保改稿后重新执行估时与审核。
- 修改测试样例，使其覆盖带货、引流、活动推广及题目指定的异常路径。

仓库已执行 116 项自动测试、45 组离线 CLI 用例和 3 条全角色协议测试路径。测试命令、结果文件和对应 Trace 见 [效果评估](03-evaluation.md)。
